# dsh-fusion-remote

> ⚠ **开发中。** rendezvous 服务器尚未就绪，当前可用的是**局域网直连**。
> 跨网络连接会在服务器上线后启用 —— 代码里已留好那条路径。

把本机的 DSH 后端换成另一台设备上的 DSH。**服务端与客户端是同一个插件**，
**两边都装才能连**（协议在插件层，天然如此）。

## 三种后端模式

| 模式 | 壳指向哪 | 说明 |
|---|---|---|
| `local` | 本机引擎端口 | 插件不参与 |
| `remote` | **隧道端口** | 本机引擎可继续空闲跑，也可停掉（用户选） |
| `side` | 本机引擎 + 侧边栏指向隧道端口 | 两个 DSH 并排 |

**壳不需要懂协议**，它只需要知道「指向哪个端口」。

## 两种配对方式，安全强度不同

| 方式 | 怎么用 | 强度 |
|---|---|---|
| **6 位数字码** | 两边同屏显示，用户肉眼看是否一致 | 取决于**用户真的比对**。跳过比对等于没有这一层，所以不提供「跳过」 |
| **二维码** | 屏幕大的一侧显示，有相机的一侧扫 | **更强** —— 二维码是带外信道，不经过可能被中间人的网络 |

UI 上要如实标注差别，而不是并排摆着让人以为一样。

## 限速：短码唯一的安全性来源

**不是可选加固，是必需项。** 算一下就知道：

| 码长 | 无限速（脚本 1000 次/秒） | 有本模块的指数退避 |
|---|---|---|
| 6 位（默认） | **8 分钟** | **14 年** |
| 8 位 | 14 小时 | 更久 |

**没有限速的 6 位码不是「弱密码」，是等于没有密码。**

三层：单来源指数退避（前 3 次不罚，正常用户也会敲错）· 全局失败计数与告警
（识别分布式猜解）· 持久化（重启不清零）。

**成功只清「单来源」，不清全局** —— 「先猜中一次再继续猜」正是攻击者会做的，
清全局等于给他发奖励。

出处：[Magic Wormhole 的攻击模型](https://github.com/magic-wormhole/magic-wormhole/blob/master/docs/attacks.rst)
把它当成主要威胁写在自己的「已知漏洞」里。

## 设备 ID

```
REOIB6H-E5WAMN3-7X4RJ2M-CSZD3XQ-VKBNCLY-Y5VKV2U-3SBMECM-DMAA
```

公钥的 SHA-256 → base32（52 字符）+ **Luhn mod 32 校验位**，每 7 字符一组。
实测**单字符错误 404/404 全部检出，相邻换位 50/50 检出**。

> 没有校验位时，输错一位的表现是「连不上，原因不明」——
> 用户会怀疑网络、防火墙、配对流程，唯独不会怀疑自己少打了一个字符。

**ID 是展示形式，不是身份** —— 校验永远用原始公钥。

## 跨境闸

两层，因为「跨境」有两种含义：

- **握手时**：校验对端地址。**私有地址跳过检查**（含 EasyTier/Tailscale 用的
  CGNAT `100.64/10`）—— 内网物理上跨不了境，对它们也查归属会把正常的内网直连误杀
- **连接期间**：每 30 秒检查本机出口（**只在「对端是公网」时才查**，
  因为局域网内查出口没有意义，而且那次查询本身就可能是出境的）

判定用**内置的中国 IP 段表**（APNIC 数据，8794 条 CIDR → 4116 个合并区间，
134 KB，0.83 µs/次查找）。**不用在线 API** —— 为判断有没有出境而先出一次境，
这个自相矛盾在真实实现里非常常见。

## 认证

Ed25519 双向挑战应答 + 6 位短认证串 + 公钥 pin。

**两边都必须验**：只验一边（常见的是只让服务端验客户端）意味着另一边不知道
自己在跟谁说话 —— 中间人可以冒充服务端，客户端照样把数据交出去。

**公钥变更即拒绝**，不静默更新 —— 静默更新会把中间人攻击变成透明代理。

**明确不做**：不做免确认的「记住这台设备」（那会把配对码那层削掉）；
不做基于 IP 的信任（IP 可伪造，公钥不行）；密钥材料不进任何日志。
